Espaço, raios e sombras

Grade de 4px para todo espaçamento, seis raios com destino declarado e cinco sombras que indicam altura. Os raios são a assinatura do sistema — errar o raio é o jeito mais rápido de algo não parecer ZAZ.

01Princípios

O que decide uma medida

Tudo é múltiplo de 4

Nenhum espaçamento do sistema é 5px, 7px ou 15px. A grade de 4 pixels é o que faz elementos diferentes, feitos por pessoas diferentes, se alinharem sem combinar nada. Quando você precisa de "só um pouquinho mais", a resposta é o próximo degrau da escala — não um número novo.

O raio diz o que a coisa é

Um raio de 12px diz "isto é um controle: clique". Um raio de 16px diz "isto é um container: leia". Um raio infinito diz "isto é um ponto ou uma pessoa". Trocar o raio troca o significado, e é o erro que mais rápido faz uma tela parecer de outro produto.

A sombra é altura, não decoração

Cada sombra corresponde a uma distância da superfície: quanto mais perto do usuário, mais difusa. Por isso um modal não usa a sombra de um card, e um card não usa a de um modal — a sombra errada faz o olho entender a ordem das camadas ao contrário.

O espaço separa por significado

A distância entre dois elementos declara o quanto eles se relacionam. Rótulo e campo ficam a 8px porque são a mesma coisa; dois campos ficam a 24px porque são coisas diferentes. Quando o espaço interno de um grupo é igual ao externo, o olho não sabe mais onde o grupo termina.

Anatomia de uma caixa: espaço externo, borda, espaço interno e conteúdo — mais o raio e a sombra, que definem o tipo e a altura.

O sistema assume box-sizing: border-box. Isso quer dizer que espaço interno e borda contam dentro da largura declarada: um campo com width: 100% e 16px de padding ocupa 100%, não 100% + 34px. O reset do .zaz-root aplica essa regra — sem ela, todo controle estoura o container.

Em código

O espaçamento vem do gap, não de margens soltas
/* Certo: o pai declara a distância uma vez */
.formulario {
  display: flex;
  flex-direction: column;
  gap: var(--zaz-space-6);   /* 24px entre campos */
}

/* Errado: margem no filho colapsa, dobra e some conforme o vizinho */
.campo { margin-bottom: 24px; }

Acessibilidade em espaço

Meta do sistema: WCAG 2.1 nível AA

Alvo de toque

  • A WCAG 2.1 pede 44 × 44px de área acionável em tela de toque. A densidade padrão do sistema dá 40px — 4px abaixo.
  • Em telas pensadas para celular, use a densidade baixa (56px) ou aumente a área clicável em volta do controle sem aumentar o controle.
  • Dois alvos vizinhos precisam de pelo menos 8px entre si. Botões colados viram um alvo só para quem tem tremor.

Pendência conhecida: a densidade padrão de 40px atende bem a mouse, mas fica abaixo do mínimo de toque. Enquanto o Apolo for um console de desktop isso é aceitável; qualquer tela pensada para celular precisa subir de densidade.

Espaço em branco é acessibilidade

  • Texto sem respiro é mais difícil para dislexia e déficit de atenção: a linha seguinte compete com a anterior. Os 24px entre blocos não são estética.
  • A WCAG tem critério próprio para isso (Text Spacing): a página precisa continuar funcionando se o usuário aumentar entrelinha e espaço entre parágrafos. Layout com altura fixa quebra nesse teste.

Sombra não é informação

A sombra indica altura para quem enxerga bem. Ela não pode ser o único sinal de que algo é interativo, está selecionado ou está por cima — quem usa alto contraste ou tema forçado pelo sistema operacional não vê sombra nenhuma. O sinal precisa estar também na cor, na borda ou no texto.

Movimento reduzido

Todo bloco de animação vem acompanhado de @media (prefers-reduced-motion: reduce) zerando a duração — o reset do .zaz-root já faz isso para o sistema inteiro. Para quem tem sensibilidade vestibular, animação decorativa causa mal-estar físico; não é preferência estética.
