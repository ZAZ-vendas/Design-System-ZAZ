Design System · Fundamentos · Tema

Tema claro e escuro

O Apolo é um console que fica aberto o dia inteiro, e boa parte do time trabalha no escuro. O tema não é enfeite: é a mesma tela em duas superfícies. Quem escreve com token não precisa pensar nisso — quem escreve hexadecimal, sim, e é onde erra.

01Princípios

O que sustenta os dois temas

Toda cor se escreve em par

Esta é a regra chata e inegociável: o claro e o escuro juntos, na mesma linha. Quem escreve só a metade clara produz uma tela que funciona na sua máquina e some na do vizinho. Usando os tokens do sistema não existe par a escrever — a variável já carrega os dois valores.

A pessoa escolhe, e a escolha persiste

O tema é ligado por classe, nunca por prefers-color-scheme. Metade do time usa o sistema operacional no claro e o Apolo no escuro; respeitar o SO à força tiraria essa escolha. A preferência fica no localStorage e vale entre sessões.

Só os papéis trocam de valor

Nenhuma cor de escala é redefinida no escuro: --zaz-brand-600 vale a mesma coisa nos dois temas. Trocar de tema é trocar o valor de um papel, nunca a classe de um componente. É por isso que components.css não tem nenhuma regra .dark.

03O que muda e o que não muda

A lista que evita a maioria dos erros

Trocam de valor

  • Fundos e bordas (--zaz-bg-*, --zaz-border*)
  • Texto (--zaz-text*)
  • --zaz-primary-text, que clareia
  • O trio de cada status, que vira véu translúcido
  • As sombras, que perdem o tingimento azulado

Não trocam

  • A escala de marca inteira
  • --zaz-primary como fundo
  • --zaz-on-primary, branco nos dois
  • As cores das marcas parceiras
  • A paleta de séries de gráfico

O véu resolve o hover sozinho

Fundo de hover, linha de lista tocada e item de navegação ativo saem de --zaz-veil e --zaz-veil-strong, que nascem de color-mix() sobre o --zaz-primary-text. Como o primary-text já muda no escuro, o véu acompanha — e nenhum componente precisa de uma regra .dark gêmea só para pintar fundo suave.

04Aplique antes do primeiro paint

O detalhe que separa app nativo de site

A leitura do localStorage e a classe no <html> vão num <script> inline no <head>, antes de qualquer render. Se isso rodar num useEffect, a página abre branca e escurece depois — o flash é visível e some a impressão de app nativo.

Esta própria página faz assim: veja o <script> de três linhas no topo do HTML.

Por que no <head> e não no fim do <body>: o navegador pinta a primeira tela assim que tem CSS suficiente. Um script no fim do corpo roda depois dessa pintura — tarde demais. No <head>, sem defer, ele roda antes, e a página já nasce escura.

Como ligar o tema

Três pedaços, e nenhum deles é opcional

1. Antes do primeiro paint

no <head>, sem defer, antes de qualquer render
<script>
  // try/catch porque localStorage lança em janela anônima com
  // cookies bloqueados — e aí a página inteira deixaria de abrir.
  try {
    if (localStorage.getItem('tema') === 'dark')
      document.documentElement.classList.add('dark');
  } catch (e) {}
</script>

2. O botão que alterna

a classe vai no <html>, não no <body>
botao.addEventListener('click', () => {
  // toggle devolve true quando a classe ficou aplicada
  const escuro = document.documentElement.classList.toggle('dark');
  try { localStorage.setItem('tema', escuro ? 'dark' : 'light'); } catch {}
});

3. As cores, que você não escreve duas vezes

com os tokens do sistema não existe par a escrever
.minha-tela {
  background: var(--zaz-bg-surface);
  color: var(--zaz-text);
  border-color: var(--zaz-border);
}
/* Pronto. Os dois temas estão aqui. */

Acessibilidade no tema

Meta do sistema: WCAG 2.1 nível AA

Os dois temas têm a mesma meta

Não existe "o escuro é decorativo". Todo par de cor precisa atingir 4,5:1 nos dois temas — e é justamente no escuro que os erros aparecem, porque uma cor pensada para fundo claro costuma perder contraste sobre fundo escuro.

ParClaroEscuroSituação
Texto sobre superfície9,7:115,8:1✓ AAA
Texto de apoio sobre superfície4,8:15,9:1✓ AA
Marca como texto9,7:17,2:1✓ AAA
Marca como fundo, com branco em cima9,7:19,7:1✓ AAA
Marca de fundo usada como texto no escuro—2,7:1✕ é o erro que a regra de ouro evita

Escuro não é preto puro

O fundo escuro do sistema é neutral-950, não #000000. Texto branco sobre preto absoluto produz um contraste tão alto que causa halation — o borrão que faz a letra vibrar, especialmente para quem tem astigmatismo. O mesmo vale do outro lado: o tema claro usa neutral-50, não branco puro, no fundo da aplicação.

A escolha é do usuário

  • O alternador precisa ser alcançável por teclado e ter nome acessível ("Alternar tema").
  • Não force o tema por prefers-color-scheme sem oferecer a troca: quem usa tema claro por necessidade visual e SO escuro por outro motivo fica sem saída.
  • A preferência precisa persistir. Reaplicar a cada visita é pedir que a pessoa resolva o mesmo problema todo dia.

A transição também respeita movimento reduzido

A troca de tema anima transition-colors por 300ms apenas no shell e no header. Com prefers-reduced-motion: reduce, a duração é zerada pelo reset do sistema e a troca acontece instantaneamente — que é o comportamento certo, não uma degradação.
